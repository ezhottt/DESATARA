# DESATARA Production Readiness

**Decision baseline:** `PRODUCTION READY = NO` until all mandatory evidence below is current and machine-verifiable.

## Local validator

Run:

```text
php artisan desatara:check-readiness --production
```

The command checks safe configuration properties and the presence of opaque evidence references. It never prints their values. Configure these references through the deployment secret/environment mechanism; do not commit them:

```text
DESATARA_TLS_EVIDENCE
DESATARA_BACKUP_EVIDENCE
DESATARA_RESTORE_EVIDENCE
DESATARA_QUEUE_EVIDENCE
DESATARA_SCHEDULER_EVIDENCE
```

These references are pointers to operator-controlled records, not proof by themselves. A passing local command does not promote the release to production-ready.

## Mandatory external evidence

Record, at minimum:

- TLS and production configuration/header verification;
- PostgreSQL migration verification;
- backup availability and integrity verification;
- isolated restore smoke, including private documents and historical/report integrity;
- healthy queue worker and scheduler evidence;
- staging smoke and post-deploy smoke;
- deployment identifier, rollback/recovery path, and unresolved P0 = zero.

Provider-specific commands, hostnames, credentials, retention, RPO, and RTO remain intentionally unspecified until the target environment is approved. See [`BACKUP-RESTORE.md`](BACKUP-RESTORE.md) for the provider-neutral recovery procedure.

## Pre-launch security re-audit - 2026-10-07

**Verdict: `NO-GO — NOT READY FOR PRODUCTION`.**

This checkpoint was rebuilt against current `origin/main` rather than applying an older dirty patch blindly. Safe code findings were reproduced with regression tests before remediation.

### Patched locally on the security hardening branch

- Report review/revision now requires `reports.export` at both route and service boundaries; a `reports.view`-only member is denied for both operations.
- Framework serving for the private-root `local` filesystem is disabled.
- User-uploaded evidence enters `pending / quarantined` state and is not downloadable until its malware status is exactly `clean`.
- Authorized clean-document access records a minimal `document.download.authorized` audit event without filename, storage path, or checksum.
- Server-generated report and interoperability JSON artifacts are marked `clean / stored`; quarantine applies to untrusted uploads rather than trusted server-generated bytes.
- Expensive mutation endpoints are throttled: document upload at 10/minute; B26 import preview/commit and legacy direct import/export at 5/minute.
- Legacy/direct JSON import is limited to 1,000 rows at the HTTP boundary and validates each row as an array.
- Shared interoperability service has a 5,000-row hard ceiling so the existing B26 CSV/XLSX 5,000-row contract remains intact.
- Client-supplied asset `uuid`, `lifecycle_status`, and `verification_status` are removed from normalized import payload; server-owned lifecycle/verification state is applied on commit.

Current npm status is therefore **2 critical, 0 high**. Both remaining audit entries have one root: direct dev dependency `concurrently@10.0.5` pins `shell-quote@1.9.0`, which is affected by GHSA-pqg4-j6r4-53mv. The available automatic npm force-fix changes the `concurrently` line incompatibly, so no force fix or unreviewed override was applied.
